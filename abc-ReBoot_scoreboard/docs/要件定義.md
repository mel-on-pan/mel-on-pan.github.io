# クイズ大会スコア＆問題表示システム 要件定義書 (簡易版)

## 1. システム概要
対面イベントにおける競技クイズの進行・スコア管理および観客向け問題配信を行うシステム。
会場のメインスクリーンにはビジュアル重視のスコアボードを表示し、観客・プレイヤーは各自のスマートフォンで手元に最適化された問題・解答をリアルタイムに閲覧する。

---

## 2. システム構成 (3画面モデル)

```
[ 運営/司会者用 PC (index.html) ]
  ├── (ローカル同期) ──> [ メインスクリーン (screen.html) ] (プロジェクター表示)
  └── (リアルタイム通信) ─> [ 観客用スマホ (viewer.html) ] (各自のブラウザ)
```

1. **司会・運営用画面 (`index.html`)**: 問題送り、正解/不正解判定、加減点、状態管理を行う操作パネル。
2. **メインスクリーン画面 (`screen.html`)**: プロジェクター・大画面に全画面表示するスコア専用ボード。
3. **観客・プレイヤー用画面 (`viewer.html`)**: 観客がスマートフォン等でQRコードからアクセスし、手元で問題文および正解・解説を確認する画面。

---

## 3. 機能要件

### 3.1 メインスクリーン画面 (スコアボード特化)
* **縦書きネームプレート表示**: 黒背景、白文字による競技クイズ風の縦書きプレイヤー名表示。
* **状態・順位バッジ**: ネームプレート上部に「1st」「2nd」などの勝ち抜け順位や「LOSE」等の状態タグを表示。
* **リアルタイムスコア表示**: ネームプレート下部に現在の得点を大きく表示。
* **ペナルティ/誤答表示**: 最下部に正解数(〇)および誤答数(×)のカウントを表示。
* **演出機能**: 正解・誤答時、あるいは判定時の視覚的ハイライト・アニメーション。

### 3.2 観客・プレイヤー用画面 (スマホ最適化)
* **リアルタイム問題文表示**: 運営の進行に合わせて、50〜80字程度のオープンクエスチョン（1文）を画面手元に即時表示。
* **正解・解説のタイミング同期**: 運営が「正解表示」操作を行うまで正解は伏せられ、操作と同時に一斉表示。
* **レスポンシブ UI**: 選択肢や画像表示を省き、テキストの可読性を極限まで高めたシンプル設計。

### 3.3 司会・運営用画面
* **問題進行コントロール**: `次の問題` / `スルー` / `正解表示` / `セットリセット`
* **ワンタップスコア操作**: 各プレイヤーごとの `正解 (+1)` / `誤答 (×)` ボタン。
* **リカバリー機能 (Undo)**: 誤操作時に1つ前の判定・得点状態へ戻す機能。
* **ルール判定ロジック**: 形式（例: `7○3x`, `10by10` 等）に応じた自動勝ち抜け/失格判定。

---

## 4. データ要件

### 4.1 問題データ仕様 (`questions.json`)
* 50〜80字程度のテキスト問題および正解テキストのみで構成。

```json
[
  {
    "id": 1,
    "question": "燕の政治家に由来する故事で、大きな事業もまず身近なことから始めるべきだということを、「まず何より始めよ」というでしょう？",
    "answer": "まず隗より始めよ"
  }
]
```

---

## 5. 非機能要件
* **会場での視認性**: メインスクリーンは高コントラストな配色で遠くからでもスコアが認識できること。
* **リアルタイム性**: 運営者の操作からメインスクリーン・観客スマホへの反映遅延が500ms以内であること。
* **安定性・操作性**: ブラウザのリロードによるデータ紛失を防ぐため、途中経過をローカルストレージ等に自動保存できること。
