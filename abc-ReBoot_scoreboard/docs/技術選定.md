# クイズ大会スコア＆問題表示システム 技術選定書 (簡易版)

## 1. 基本方針
* **速攻プロトタイピング**: ビルドツールや複雑な環境構築を一切行わず、ブラウザとテキストエディタのみで開発・即実行可能とする。
* **サーバーレス/軽量設計**: 外部サーバーへの依存を最小限にし、ローカル環境または無料インフラで完結させる。

---

## 2. 技術スタック一覧

| 区分 | 採用技術 / ライブラリ | 選定理由・目的 |
|---|---|---|
| **フロントエンド** | HTML5 / CSS3 / Vanilla JavaScript | 外部依存なし、高速起動、ローカルファイル直開かせでも動作可能 |
| **画面間通信 (同一PC内)** | BroadcastChannel API | 運営画面 ⇔ メインスクリーン間の同期をサーバーなし・ミリ秒単位で実現 |
| **端末間通信 (スマホ接続)** | PeerJS (WebRTC) または PartyKit | 観客スマホへの問題一斉配信を無料かつ最小コード量で実現 |
| **音響制御** | Howler.js | WEBブラウザ上での効果音（正解/誤答音など）のラグなし再生 |
| **データ保持** | LocalStorage / JSON | 途中経過のキャッシュおよび問題データの管理 |

---

## 3. 通信アーキテクチャ

### (1) 運営画面 ↔ メインスクリーン (PC内ブラウザ同期)
ブラウザ標準の `BroadcastChannel API` を使用。
同一ブラウザ内の別タブ・別ウィンドウ間でメッセージを即時共有するため、インターネット接続も不要。

```javascript
// 運営画面・メインスクリーンで共通のチャンネルを開く
const channel = new BroadcastChannel('quiz_channel');

// 運営画面からの送信例
channel.postMessage({ type: 'UPDATE_SCORE', playerId: 'p1', score: 4 });

// メインスクリーンでの受信例
channel.onmessage = (event) => {
  const data = event.data;
  // スコアボード描画更新
};
```

### (2) 運営画面 ↔ 観客用スマホ (マルチデバイス同期)
`PeerJS` 等を利用したWebRTC P2P通信、または `PartyKit` などの超軽量リアルタイム通信ライブラリを採用。
運営画面がホスト（親機）となり、生成されたQRコードをスマホで読み取ることで接続を確立する。

---

## 4. 画面レイアウト実装方針 (CSS)

* **縦書きネームプレート**: CSSの `writing-mode: vertical-rl;` を使用して、Excel版と同等以上の美しい縦書きフォント表示を実現。
* **フレキシブルレイアウト**: CSS Flexbox / Grid を用い、プレイヤー人数（8人、10人等）に応じてネームプレートの幅や配置が自動調整されるレスポンシブ構成。

---

## 5. 開発フェーズ計画

1. **Phase 1 (画面レイアウト & ローカル同期)**
   * `screen.html` (スコアボード) のCSSデザイン完成。
   * `index.html` (運営画面) から `BroadcastChannel` 経由でスコアを加減点する挙動の実装。
2. **Phase 2 (問題配信 & スマホ接続)**
   * `questions.json` のロード機能実装。
   * 観客画面 (`viewer.html`) への問題テキスト・正解テキストのリアルタイム同期実装。
3. **Phase 3 (サウンド & アニメーション)**
   * Howler.js による効果音実装、勝敗判定・演出追加。
